## Не доверяй агенту. Доверяй системе.

**noomoo — инженерный каркас для разработки ПО с агентами.**

Агенты планируют, пишут, тестируют, проходят ревью и выпускают код по правилам, которые команда действительно может обеспечить.

noomoo не верит отчёту агента о сделанном, а проверяет, что произошло в репозитории.

Для команд, которые переходят от программирования с помощью ИИ к автономной поставке ПО.

## ИИ сделал код дешёвым. Узкое место теперь — проверка.

Агенты уже реализуют функции, чинят ошибки, запускают тесты, открывают pull request и отвечают на ревью. Вопрос больше не в том, **может ли агент написать код**. Настоящие вопросы другие:

- Понял ли он требование?
- Остался ли в рамках задачи?
- Следовал ли архитектуре?
- Действительно ли добавил тесты?
- Действительно ли эти тесты запускались?
- Остаётся ли ревью в силе после последней правки?
- «Готово» — это факт или просто слова агента?

## Агент не уговорит гейт.

| Агент | noomoo |
|---|---|
| «Все тесты проходят». | **Покажи результат тестов для этой ревизии.** |
| «Я проверил изменения». | **Покажи свежий артефакт ревью для текущего кода.** |
| «Я изменил только то, что требовала задача». | **Покажи diff и докажи границы.** |
| «Задача готова». | **Докажи.** |

Статус словами — не доказательство. **Доказательство — состояние репозитория.**

## Люди задают курс. Агенты исполняют. noomoo проверяет.

1. **Опиши результат.** Требования, сценарии, фичи и задачи образуют прослеживаемую цепочку. Задача говорит, **что должно стать правдой**, а не как агенту писать код.
2. **Докажи, что задача исполнима.** До начала работы noomoo проверяет структуру, границы, связи и неоднозначность. Если задачу нельзя выполнить, не гадая, работа не начинается.
3. **План до правки кода.** План реализации становится версионируемым артефактом: реализация, контракты, тесты и решения.
4. **Дай агенту работать.** Агент реализует, тестирует, проходит ревью, исправляет и готовит поставку в отдельной ветке или worktree.
5. **Проверь, что произошло на самом деле.** noomoo проверяет Git, файлы, AST, тесты, артефакты ревью, CI и инварианты проекта.
6. **Двигайся дальше только с доказательством.** Есть нужные факты — работа идёт дальше. Нет — останавливается.

## Инструкции направляют. noomoo обеспечивает.

`CLAUDE.md`, `AGENTS.md`, промпты и навыки полезны. Но они по-прежнему зависят от того, прочтёт ли агент их, запомнит, поймёт и выполнит. noomoo их дополняет.

CI говорит, собирается ли код и проходят ли тесты. **CI проверяет код. noomoo проверяет жизненный цикл разработки вокруг него.**

**Пусть агенты делают больше работы. Но не ставят оценки сами себе.**

## noomoo для Claude Code

noomoo — инженерный слой контроля для агентов. Он проверяет, что произошло в репозитории, а не верит отчёту агента: детерминированные проверки документов, Git, тестов и CI, гейты жизненного цикла, привязанные к текущей ревизии, состояние ревью и статус проекта.

Плагин приносит процессы noomoo в Claude Code в виде навыков. Каждый навык вызывает ядро noomoo, установленное в проекте; ядро — источник правды для проверки и приёмки. Фазу работы закрывает код возврата команды ядра, а не отчёт агента. Плагин не заменяет Git, ваши тесты, CI и правила репозитория.

## Требования

Плагин не устанавливает ядро: добавьте пакет noomoo в каждый проект сами. Без него навыки попросят его установить и остановятся.

- Node.js 20 или новее и Git.
- Пакет ядра noomoo в проекте, добавленный тем менеджером пакетов, который проект уже использует:

```bash
npm install -D noomoo
pnpm add -D noomoo
yarn add -D noomoo
bun add -d noomoo
```

- GitHub CLI (`gh`) с выполненным входом — для шагов `/noomoo:task`, которые читают pull request, прогоны CI и личность ревьюера.

Superpowers — по желанию: если он установлен, `/noomoo:task` поручает его навыкам проектирование, реализацию через тесты, ревью и проверку; без него навык проходит те же фазы сам. Оба пути закрывают каждую фазу одними и теми же командами ядра.

## Начало работы

1. Установите пакет ядра, как показано выше.
2. В Claude Code выполните `/noomoo:setup`. Он показывает план установки и ничего не меняет до подтверждения. То же из терминала: `npx --no-install noomoo setup` печатает план, `npx --no-install noomoo setup --yes` применяет его и записывает в `.noomoo/setup-manifest.json`.
3. Влейте установку в основную ветку отдельным pull request из служебной ветки, например `chore/noomoo-setup`.
4. Выполните `/noomoo:start`, чтобы увидеть, где находится проект и что делать дальше.

`/noomoo:rollback` снимает установку по её манифесту: сначала показывает план и сохраняет файлы, которые вы изменили после установки.

## От идеи до pull request

noomoo покрывает весь путь поставки, и каждый шаг оставляет документ или факт, который проверяет следующий шаг:

1. **Intake.** `/noomoo:intake` превращает сырой материал в предложение для владельца.
2. **Спецификация.** `/noomoo:spec` описывает работу прослеживаемой цепочкой: требование → сценарий → фича → задача.
3. **Проектирование.** `/noomoo:architect` пишет записи решений, архитектурные срезы и документы данных.
4. **Готовность.** Задача берётся в работу, только когда гейт готовности признаёт её исполнимой без догадок.
5. **План.** План реализации — версионируемый документ, который проходит ревью и утверждается до правки кода.
6. **Поставка.** `/noomoo:task` проводит задачу через реализацию с тестами вперёд, ревью и полную проверку до pull request.
7. **Отчёт.** `/noomoo:report` фиксирует находки или изменение живой системы вместе с доказательствами.

Шаблоны документов и рубрики ревью поставляются с пакетом ядра (`node_modules/noomoo/docs/`). Документы создаются командой `noomoo scaffold`, которая печатает точную форму, поэтому имена, разделы и ссылки остаются проверяемыми.

## Навыки

| Навык | Что делает |
|---|---|
| `/noomoo:start` | Показывает, где находится проект, и следующий шаг — из `noomoo next`. |
| `/noomoo:status` | Показывает статус проекта: защиту, последнюю проверку, открытую работу, пункты, требующие внимания. Только чтение; проверку ради обновления статуса не запускает. |
| `/noomoo:doctor` | Проверяет установку noomoo в репозитории. Только чтение, работает и до установки. |
| `/noomoo:setup` | Устанавливает noomoo в репозиторий: показывает план, применяет его по вашему «да». |
| `/noomoo:rollback` | Откатывает установку по манифесту: показывает план, применяет его по вашему «да». |
| `/noomoo:validate` | Проверяет документацию проекта командой `noomoo validate`. Ничего не пишет. |
| `/noomoo:spec` | Описывает новую работу как требование, сценарий, фичу и задачу до того, как она будет сделана. |
| `/noomoo:task <TASK-NNN>` | Проводит одну задачу от её документа до pull request через гейты noomoo. Точка входа для поставки задачи. |
| `/noomoo:architect` | Пишет запись решения, архитектурный срез или документ данных. |
| `/noomoo:intake` | Превращает сырой материал или пересланное сообщение в предложение intake для владельца. |
| `/noomoo:report` | Пишет отчёт о находках или об изменении живой системы вместе с доказательствами. |

## Что запускает плагин

Навыки запускают ядро менеджером пакетов проекта и никогда его не скачивают: `npx --no-install noomoo`, `pnpm exec noomoo`, `yarn exec -- noomoo` или `bun x --no-install noomoo`. Если пакета нет, навык просит его установить и останавливается.

Навыки не разрешают заранее ни одной команды оболочки и ни одной правки файла. Claude Code спрашивает вас перед каждой командой ядра и каждой правкой; из этого запроса можно разрешить команду для проекта.

У плагина два хука:

- **SessionStart** читает только `package.json` и `.noomoo/setup-manifest.json`. Если проект перечисляет noomoo, но установка не выполнялась, он печатает одну строку с подсказкой запустить `/noomoo:setup`. Процессов он не запускает.
- **PostToolUse** на `Edit` и `Write` ничего не делает, пока не выполнены три условия: в проекте есть `.noomoo/setup-manifest.json`, вы согласились запускать noomoo в этом репозитории (setup записывает согласие в `~/.config/noomoo/trusted-repos.json`), и ядро установлено локально. Тогда он запускает `noomoo claude-hook-docs` через менеджер пакетов проекта, передаёт ему событие правки, ждёт не дольше 20 секунд и возвращает вывод Claude как контекст.

Ни один хук не устанавливает пакеты, не открывает сетевых соединений и не записывает доверие. Установка, доверие и правила репозитория остаются явными операциями noomoo. Для явно одобренной автоматизации доверие к проекту можно передать через `NOOMOO_TRUST_PROJECT=1`; сам noomoo эту переменную никогда не выставляет.

Сам плагин ничего не устанавливает в Git или GitHub. Когда вы подтверждаете установку, ядро может добавить Git-хуки в `.githooks/` (`pre-commit` и `pre-push` запускают проверки документации, `commit-msg` отклоняет подписи ИИ). Если хуками проекта управляет noomoo, setup может настроить `core.hooksPath` на каталог хуков noomoo. Существующая настройка хуков, которой управляет пользователь, сохраняется по правилам владения setup. Setup также добавляет процесс GitHub Actions `.github/workflows/noomoo.yml`. Защиту веток, вебхуки и секреты на GitHub он не меняет. `/noomoo:rollback` убирает всё это.

`/noomoo:task` работает в отдельной ветке, в Git worktree под `.worktrees/`, если проект этого просит. Он пушит ветку и открывает pull request только после вашего явного разрешения и никогда не вливает его.

## Данные и доступ к сети

- В плагине нет сетевого кода и телеметрии. Публичный пакет ядра noomoo не содержит отправителя телеметрии.
- Ядро пишет внутри вашего репозитория: документы, конфигурацию, Git-хуки, процесс CI и локальный журнал команд `docs/validation/events.jsonl`, исключённый из git. Setup показывает каждый файл, который создаст, до записи.
- Команды, которые читают pull request, прогоны CI или личность ревьюера, обращаются к GitHub API с вашим токеном или через ваш вход в `gh`.
- Ревью моделью (`task-ready`, `plan-ready --judge`, `estimate`) запускает Claude CLI, установленный на вашей машине, с инструментами только для чтения и передаёт ему текст проверяемого документа. Этот текст уходит провайдеру Claude под вашей учётной записью и на ваших условиях.
- Git, `gh` и Claude Code обращаются к своим сервисам со своей аутентификацией и по своим правилам.

## Установка плагина

Установите плагин в Claude Code из маркетплейса в этом репозитории:

```bash
/plugin install noomoo --marketplace TaskForceNow/noomoo
```

В Claude Code старше 2.1.275 сначала добавьте маркетплейс:

```bash
/plugin marketplace add TaskForceNow/noomoo
/plugin install noomoo@noomoo
```

Каталог плагинов Claude станет вторым каналом, когда будет доступен.

Запасной путь — загрузить архив выпуска на одну сессию. Скачайте `noomoo-plugin-<version>.zip` и `SHA256SUMS` из одного и того же [выпуска](https://github.com/TaskForceNow/noomoo/releases) noomoo, проверьте архив и запустите Claude Code с ним:

```bash
shasum -a 256 -c SHA256SUMS --ignore-missing
claude --plugin-dir noomoo-plugin-<version>.zip
```

Используйте архив плагина того же выпуска, что и пакет ядра в вашем проекте.
